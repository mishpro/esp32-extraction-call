# Протокол в MVP — что реализуем сейчас

Источник правды: `drafts/Протокол.md` (v1.0, 2026-11-02). Ниже — что входит в MVP и что отложено. Мои ранние черновики (`type`/`payload` вложенностью) **не используются**: в спецификации поля плоские, тип — в `t`.

## Транспорт

`ws://<host>:8000/ws`, JSON UTF-8 без BOM, максимум сообщения 4096 байт, ping каждые 15 с, 3 пропуска → закрытие сессии, таймаут ожидания ACK 30 с.

## Сообщения MVP

| Тип | Направление | Поля | Когда |
|---|---|---|---|
| `hello` | клиент → сервер | `v`, `t`, `role`, `token`, `id`, (`fw` для device) | сразу после Upgrade; таймаут 10 с |
| `hello_ok` | сервер → клиент | `v`, `t`, `session`, `t_epoch`, `peer{id,online,state,remaining_s}` | успешная авторизация |
| `press` | кнопка → сервер → приложение | `v`, `t`, `seq`, `t_epoch`, (`from`) | нажатие BTN1 |
| `ack` | в обе стороны | `v`, `t`, `seq`, `ok`, `stage` (`server`/`delivered`) | приём и доставка |
| `status` | сервер → обоим | `v`, `t`, `t_epoch`, `device{online,state,remaining_s,fw}`, `app{online}` | смена живости/состояния, старт сессии |
| `ping` / `pong` | обе | `v`, `t`, `t_epoch` | сервер 15 с; кнопка дополнительно 20 с |
| `error` | сервер → клиент | `v`, `t`, `code`, `msg`, (`seq`) | нарушение/отказ |

Коды ошибок: `auth_failed` (close 4401, без reconnect), `bad_request` (4400), `bad_duration`, `no_peer`, `duplicate` (игнорировать), `internal` (1011, reconnect с backoff).

Close-коды: 1000 штатно, 4400 нарушение протокола, 4401 аутентификация, 1011 внутренняя ошибка.

## Отложено на следующие инкременты

| Что | Когда | Примечание |
|---|---|---|
| `timer` (приложение → кнопка, `duration_s` 60…86400, `deadline_t`) | S4 | в MVP не реализуем |
| `cancel` | S4/S8 | |
| Состояния `COUNTDOWN`, `ARRIVED`, `NO_ACK` | S4 | |
| `peer.remaining_s` / `device.remaining_s` (ненулевые) | S4 | в MVP всегда `0`/нет |
| Персистенция `last_timer` | S4 | `last_press`/`last_status` персистим уже в MVP |
| Регистрация push-токена | S6 | расширение Протокола: `register_push` |
| Авторизация включением (`AUTH_REQUIRED=true`) | после MVP | код готов с S1 |

## Обязательные правила (из §2)

1. До `hello` сервер не принимает других сообщений → close 4400.
2. Таймаут `hello` — 10 с → close 4400.
3. Токен не передаётся в URL и не пишется в лог.
4. Повторный `hello` в той же сессии → close 4400.
5. Сервер может закрыть соединение в любой момент — клиент переподключается сам (§6).

Backoff (§6): `min(60, 2^attempt) ± 20 %`; кнопка в MVP — максимум 10 с (всегда ACTIVE), приложение — максимум 60 с; счётчик сбрасывается после `hello_ok`.

## Идентификаторы (§3)

`device_id` — 8 hex, кнопка генерирует при первом запуске, хранит на плате. `app_id` — 8 hex, приложение генерирует при установке, хранит в `EncryptedSharedPreferences`. `seq` — монотонное целое от 1 у каждого отправителя, не хранится; защита от дублей (сервер игнорирует дубли).
