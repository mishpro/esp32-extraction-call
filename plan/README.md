# Guidecaller — план проекта

Дата: 2026-11-26. Статус: **MVP S0–S3 замкнут** — S0/S1/S2 закрыты, S3.5–3.8 проверены на эмуляторе Android 16 и реальном CMF Phone 1 (нажатие → push → `ack` → `WAIT ETA`). Дальше S4 и S6.
Копия этого плана продублирована в репозитории: `plan/README.md` (и соседние файлы).

## 1. Что делаем

Кнопка эвакуации. Человек A жмёт кнопку → сигнал уходит человеку B в приложение → B вводит время → на кнопке A идёт отсчёт.

## 2. MVP (этот инкремент)

Вертикальный срез **в одну сторону**: нажатие кнопки → WS-сервер → приложение → уведомление.

Вне MVP (следующие инкременты, в порядке §5):

- обратный путь `timer` → отсчёт на кнопке (`COUNTDOWN`, `ARRIVED`);
- BLE-провижининг конфигурации;
- FCM-уведомления (решено: FCM, но MVP — без него);
- питание/корпус, deep sleep;
- кнопка «стоп» (`cancel`).

## 3. Зафиксированные решения

| Область | Решение |
|---|---|
| Транспорт | `ws://<host>:8000/ws`, JSON, без TLS (принятый риск) |
| Протокол | `drafts/Протокол.md` v1.0 — источник правды для трёх реализаций |
| Сервер | Python 3.12 + FastAPI + uvicorn, один процесс: HTTP + WS |
| Прошивка | MicroPython 1.29.0 (`ESP32_GENERIC-20260824-v1.29.0.bin`) |
| WS-клиент кнопки | **пишем вручную** по §7 Протокола (в micropython-lib клиента нет) |
| Приложение | нативное Android: Kotlin + Compose, OkHttp WebSocket, Foreground Service |
| Push | FCM (шаг S6); MVP — локальное уведомление |
| Конфиг кнопки | MVP — `config.py` через `mpremote`; цель — BLE-провижининг (шаг S5) |
| Авторизация | MVP — выключена (флаг `AUTH_REQUIRED=false`), код по §4.1/§8 готов |
| Дисплей | SSD1306 128×64 I²C 0x3C, **один экран со статус-баром** |
| Ввод | одна кнопка вызова (GPIO4) + тумблер питания (аппаратно); LED не используем |
| Питание | отложено (схема в `setup.md`) |
| Deep sleep | отложено: для статуса «приложение на связи» нужен постоянный WS |
| Станция | Ubuntu 24.04, 6 CPU, 7.2 GB RAM, 60 GB free на `/home` |
| Инструменты | uv, esptool 5 + mpremote (venv), JDK 17 + Android SDK; Thonny не нужен |
| VPS | появится позже; пока сервер живёт на станции, телефон ходит по LAN-IP |

## 4. Архитектура MVP

```
BTN1 (GPIO4) ──press(seq)──► Кнопка (MicroPython) ──ws://──► Сервер (FastAPI)
                                  ▲                              │
                                  │                        ack(stage=server)
                            ack(delivered)                          │
                                  │                              ▼
                            экран: SENT              Приложение (Kotlin, Foreground Service)
                                                             │ press(from=…) → уведомление (канал signals)
```

- Реестр сервера: `devices: dict[str, DeviceSession]`, `apps: dict[str, AppSession]` (§8 Протокола).
- Сервер — ретранслятор; состояние партнёра (`peer`) возвращается в `hello_ok` и `status`.
- `press` идёт в обе стороны с `ack`: `stage=server` → кнопка показывает `SENT`; `stage=delivered` → `WAIT ETA`.

## 5. Этапы

| Этап | Содержание | DoD |
|---|---|---|
| S0 | Окружение + железо: uv, JDK 17 + Android SDK, esptool/mpremote, прошивка uV 1.29, проверка экрана и кнопки | Экран рисует текст, REPL живой, `chip_id`/`flash_id` сняты |
| S1 | Сервер: `/ws`, `/api/status`, реестр, hello/hello_ok, ping/pong, error, close-коды, JSON-логи, дубликаты `seq` | `fake_device` подключается, получает `hello_ok`, сервер логирует события |
| S2 | Кнопка: WiFi, ручной WS-клиент (§7), BTN1 → `press`, экран (статус-бар + состояние), reconnect | Нажатие на реальной плате → `press` в логах сервера, экран `SENT` |
| S3 | Приложение: OkHttp WS в Foreground Service, `hello`, приём `press`, уведомление, `ack(delivered)`, экран статуса | Нажатие кнопки → уведомление на телефоне, кнопка показывает `WAIT ETA` |
| S4 | Обратный путь: `timer`/`cancel`, `deadline_t`, `COUNTDOWN`/`ARRIVED` на кнопке, метки времени (сервер/кнопка) | Ввод времени в приложении → отсчёт на экране кнопки |
| S5 | BLE-провижининг: GATT-сервис, запись `config.json` из приложения | Конфиг меняется без USB, кнопка сама поднимает WiFi |
| S6 | FCM: Firebase-проект, data-сообщения, канал `signals` | Уведомление приходит при убитом приложении (при наличии GMS) |
| S7 | Питание: TP5100 + boost + диодная развязка, тумблер питания, deep sleep | Кнопка живёт от батареи; deep sleep не ломает логику |
| S8 | Опционально: кнопка «стоп» (BTN2, GPIO14) → `cancel` | Отмена таймера с кнопки |

S0–S3 = MVP. Порядок S1→S2→S3 обязателен: каждый следующий проверяет предыдущий на реальной стенде.

## 6. Риски

| Риск | Митигация |
|---|---|
| Ручной WS-клиент на uV (маскирование, фрагментация, ping/pong) | Ядро парсинга кадров — чистые функции без uV-импортов, тестируются на CPython; `fake_device` на CPython проверяет сервер |
| Нет GMS на целевых телефонах → FCM молчит | Foreground Service держит WS в любом случае; уведомление приходит локально |
| Android SDK съест диск/время | Ставим только cmdline-tools + platform 36 + build-tools 36 |
| Отсутствие VPS тормозит бой | Сервер одинаков на станции и VPS; деплой — systemd-юнит, без изменений кода |
| Deep sleep конфликтует с показом статуса приложения | Deep sleep — S7; до него кнопка работает постоянно |
| BLE-провижининг недооценён по объёму | В MVP конфиг через `mpremote`; BLE отложен на S5 |
