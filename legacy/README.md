Референс по железу. **Не часть текущего стека**: эти проекты на Arduino C++ / PlatformIO, текущий проект — MicroPython (§7.2 `ТЗ.md`).

Перенесены из корня репозитория в `legacy/` 3 ноября 2026. При переносе удалены сборочные артефакты `.pio/` (116 МБ) и `lamalarma/compile_commands.json` (1.5 МБ с виндовыми путями) — восстанавливаются через `pio pkg install` / `pio run`.

## `lamalarma/` — MVP кнопки

Основной проект: ESP32 + OLED + Telegram-бот. Работал.

| Файл | Содержимое |
|---|---|
| `src/main.cpp` | Точка входа: Wi-Fi, NTP, Telegram-бот, OLED, кнопка |
| `include/moon.h` | Битмап 128×64 (1024 байта), формат GFX row-major |
| `include/kitler.h` | Битмап 128×64, формат GFX row-major |
| `platformio.ini` | `esp32dev`, arduino, PlatformIO 6.1.19, arduino-esp32 2.0.x (IDF 4.4.7) |

### Что доказал код

| Факт | Основание |
|---|---|
| Дисплей — **I2C**, не SPI | `Adafruit_SSD1306 display(128, 64, &Wire, OLED_RESET)` — конструктор с `&Wire` |
| Модуль **4-пиновый**, RESET не используется | `OLED_RESET = -1` |
| Адрес **`0x3C`** | `display.begin(SSD1306_SWITCHCAPVCC, SCREEN_ADDRESS)`, `SCREEN_ADDRESS 0x3C` — явным адресом |
| **SDA=GPIO21, SCL=GPIO22** | `Wire.begin()` вызывается без аргументов → дефолтные пины варианта `esp32` (`pins_arduino.h`: `SDA = 21`, `SCL = 22`) |
| Контроллер — **SSD1306**, не SH1106 | Adafruit_SSD1306 2.5.15 не содержит поддержки SH1106 и шлёт `0x21`/`0x22`, которых у SH1106 нет. В проекте рисуется `moon` — битмап ровно 128×64 во всю ширину; при SH1106 картинка уехала бы влево на 2 px и была бы разорвана. Проект работал |
| Встроенный LED платы — **GPIO2** | `#define LED 2` + `pinMode(LED, OUTPUT)`; `digitalWrite` закомментирован — фактического мигания не было, полярность не подтверждена |

### Что код НЕ доказывает (важно)

- **Deep sleep не использовался вообще.** `loop()` — это `while (WiFi.status() == WL_CONNECTED)` с `delay(100)`. Пробуждение по кнопке не проверялось ни разу.
- **Кнопка была на GPIO5** (`#define BTN_PIN 5`) — у GPIO5 **нет RTC-функции**, ext0 его не принимает (`ESP_ERR_INVALID_ARG`). Работать в MVP не мешало ровно потому, что deep sleep не было. В текущем проекте BTN1 перенесён на **GPIO4** (RTC_GPIO10) — см. R-15 в `ТЗ.md`.
- Кнопка читалась как `digitalRead(BTN_PIN) == LOW` **без `pinMode`** — сработало потому, что GPIO5 strapping-пин с внутренним pull-up по умолчанию. У GPIO4 и GPIO27 pull-up по умолчанию выключен → в новой прошивке задавать явно (R-14).
- **Внешних светодиодов и бузера не было.** Схема из §7.3/§7.4 проектировалась, но не проверялась.
- NTP использовался (`configTime`, `ntp1.vniiftri.ru`) — в текущем проекте источник времени — сервер (§6.3).

### Секьюрити

В `src/main.cpp:14-19` лежат открытым текстом **токен Telegram-бота**, chat ID, имя и пароль Wi-Fi. Токен попал в репозиторий → считается скомпрометированным, отозвать через @BotFather. Пароль Wi-Fi сменить. В текущем проекте креды в исходниках запрещены (R-18, DoD §11.2).

## `sdd1306_test/` — проверка дисплея

Стенд из Adafruit-примера: `Adafruit_SSD1306` + `Adafruit_GFX`, вывод текста, инверсии, скролла, прямоугольников, окружностей, треугольников. Работал.

Подтверждает то же, что `lamalarma`: I2C, адрес `0x3C`, дефолтные пины `Wire` = 21/22, контроллер SSD1306 (все графические примитивы отрисовались без разрыва по ширине).

`platformio.ini`: `esp32dev`, arduino, `adafruit/Adafruit SSD1306@^2.5.15` + `adafruit/Adafruit GFX Library@^1.12.4`.

## `251126-191503-arduino-wifiscan/` — скан Wi-Fi

Стоковый пример PlatformIO (`platform-espressif32/examples/arduino-wifiscan`), скачан из интернета. **Пинов не содержит** — выводов по железу не даёт.

Полезен ровно двум: подтверждает, что радиомодуль принимает эфир и RSSI читается; и как источник `lib_deps` для восстановления библиотек.

## Что взять в текущий проект

| Откуда | Что |
|---|---|
| `lamalarma/src/main.cpp` | Подтверждение пинов дисплея и контроллера (§7.2) |
| `lamalarma/include/moon.h`, `kitler.h` | Splash-битмапы; нужен конвертер GFX row-major → page-major для SSD1306 (~20 строк) |
| Adafruit_SSD1306 2.5.15 (`pio pkg install`) | Референс init-последовательности для собственного драйвера: `init1`/`init2`/`init3`, режим `0x20 0x00`, `0x21`/`0x22`, `0x8D 0x14` |

## Чего в `legacy` нет

Буфер `.pio/` и `compile_commands.json` удалены при переносе. `lamalarma` собирается так:

```bash
cd legacy/lamalarma
pio run -e esp32dev_lamalarma
```

Зависимости подтянутся автоматически из `lib_deps` в `platformio.ini`.
